# CLAUDE.md — Waves Customer Portal

Context for Claude Code sessions working on the waves-customer-portal monorepo.

## Dev Workflow

- Start the app only when the authorized task needs runtime verification.
  Read-only audits and explanations do not require startup.
- Before startup, verify the selected checkout, command hooks, database
  environment, and integration side effects without printing credentials.
  Follow `docs/development.md`: run `worktree:setup` and the relevant
  `dev:doctor` preflight before managed startup. Frontend-only verification
  uses `dev:managed-client` (or standalone `dev:client`). Full startup
  requires a verified dedicated dev/preview database and isolated integrations.
  Managed `dev` checks readiness without migrating; `dev:migrate` is explicit.
- Diagnose task-relevant startup failures. Report unrelated failures and
  continue independent authorized work; do not expand the task to fix them.

## Project Overview

Waves Pest Control & Lawn Care — family-owned, SW Florida (Manatee / Sarasota / Charlotte counties). Custom AI-native operations platform: React/Vite frontend + Express/Node.js backend + PostgreSQL, deployed on Railway.

Three interfaces:
- **Admin portal** (`/admin/*`) — owner/operator dashboard, full business management
- **Customer portal** (`/`) — customer-facing PWA (service tracking, payments, referrals)
- **Tech portal** (`/tech/*`) — field technician mobile app (route, protocols, estimating)

## Rules

1. **Only touch what you're asked to touch.** If the task is "add a tool to the Intelligence Bar," don't refactor the route file, don't update the UI theme, don't reorganize imports in unrelated files.
2. **Don't add features that weren't requested.** No "while I'm here, I also improved..."
3. **Don't guess at business logic.** Retrieve applicable owner-approved decisions and authoritative contracts first, preserving their scope. Ask when the decision is missing, conflicting, or would change; do not ask the owner to repeat an applicable decision.
4. **Match the file's existing style.** Don't mix `D` palette with `components/ui` primitives in the same component.
5. **Don't delete or rename existing files** without explicit instruction. Don't move files between directories.
6. **Test your SQL.** Every Intelligence Bar tool runs Knex queries against PostgreSQL. Wrap uncertain tables/columns in try/catch — don't crash a tool module on one bad query.
7. **Keep the Intelligence Bar pattern.** Tool modules export `TOOLS` + `executeTool`; wire 6 lines into the route file. Don't invent a new architecture. See `server/services/intelligence-bar/README.md` for the template.
8. **Stripe is the payment processor. Square is fully phased out.** Do not reference Square in new code.
9. **All automation and site infra is native.** Do not reference Zapier, Make, Elementor, NitroPack, RankMath, or any external automation/CMS tool in new code.
10. **Plan first for non-trivial work.** For anything beyond a small, well-specified change, present a plan and get sign-off before writing code. An already-approved plan does not need another sign-off for unchanged implementation steps. Reconfirm a material change in effect, environment, scope, or risk. Investigation and proposal-only work may proceed within their authorized scope. Bring unresolved design, functionality, and intended-behavior decisions to the owner; make routine technical execution decisions within the approved scope autonomously, including review fixes, PR splits, and re-tagging Codex. For authorized shipping tasks, own review follow-through, merge clean non-blast-radius PRs, and continue already-authorized work in the same lane under `waves-ship` §§4–5; preserve its explicit stop conditions and narrower user instructions.
11. **When a mistake is caught, diagnose the cause.** Follow `/lesson` or `.claude/commands/lesson.md` to strengthen the existing rule, skill, regression check, or environment fix. Preserve task scope: proposal-only work returns proposed edits; authorized fixes include any necessary correction in the same change. Do not add permanent prose for temporary status or an already-clear rule.
12. **Never send or trigger customer-facing communications** (SMS, email, calls) — the owner sends all. Before any prod action, check for comm side effects (editing/completing/rescheduling `scheduled_services` rows can fire confirmation/reminder SMS) and route around them.
13. **Never test on real customers' live records.** "No durable writes" is not the safety bar (e.g. slot holds block real bookings). Use the staff draft-preview paths or owner-created test records; read-only DB inspection is fine.
14. **Hands-off + exception-based by default.** Deterministic green checks auto-apply with an audit trail and no bell; only exceptions park and surface; every lane keeps an env kill switch + one-click revoke. Where a human decision is genuinely required, use the email-reply approval pattern — a tokenized email to contact@ answered by replying "approved"/"not approved", fail-closed, at-most-once (current in-repo exemplar: the newsletter proof flow in `server/services/newsletter-proof.js`; a generalized module is in flight on PR #3024) — never a park-on-portal-visit queue. Never extend email-approval to customer comms, money movement, or gate flips.
15. **Find the existing mechanism before building one.** Search for the nearest existing implementation first. Canonical paths that must not grow siblings: surcharge math = `computeChargeAmount` (`server/services/stripe-pricing.js`), tracker state = `server/services/track-transitions.js`, ET wall-clock = `server/utils/datetime-et.js` on the server and `client/src/lib/timezone.js` in React (the client companion — never import the server module into the Vite bundle), admin auth = `adminAuthenticate` + role check from `server/middleware/admin-auth.js` (router-level `router.use(…)` in `admin-*.js` files; per-handler on mixed public/staff routers like `badges.js`), per-user feature flags = the `user_feature_flags` DB read via `useFeatureFlag` on the client and `isUserFeatureEnabled` (`server/services/feature-flags.js`) for authoritative server-side checks, release/dark-ship gates = `GATE_*` env flags via `server/config/feature-gates.js` (distinct mechanisms — per-user capability vs deploy-wide rollout), Intelligence Bar tools = `TOOLS` + `executeTool`. Extending the canonical path beats a working local duplicate.
16. **Make the smallest coherent change.** Prefer the shared mechanism over a local workaround, but don't generalize past the demonstrated requirement: no single-use wrappers, factories, or config, and no release machinery (compat layers, dual-writes, fallback paths) beyond the standard `GATE_*` dark-ship pattern unless a specific deployment risk is named.
17. **Trace the change end-to-end before claiming done.** UI → route → service → DB → response → UI state, plus side effects (webhooks, crons, SMS, cache, analytics). Verify column names, APIs, and env vars against the code — never invent them.
18. **Contracts get deliberate treatment; internals don't.** Identify consumers before touching a boundary: DB schema and CHECK-constrained values, public `/:token` routes (contracts in `docs/public-route-contracts.md`), every inbound webhook payload shape — the provider owns the contract, so this covers any webhook route mounted in `server/index.js` (today: Stripe, Twilio, SendGrid, Resend, Bouncie, the ElevenLabs voice-agent), including ones added after this list, endpoints consumed by the iOS and Android apps (push/app-link payloads included), Astro spoke-fleet form posts and feeds, the retained V1 named exports, persisted identifiers. Internal shapes (a handler's private helpers, local state, query structure) may change without ceremony once their consumers are migrated — but every repository-wide correctness and security rule (AGENTS.md P0/P1: auth, parameterized SQL, surcharge math, ET handling, status constraints) still applies inside handlers.
19. **Remove the code you supersede.** When replacing behavior, delete the obsolete helper, flag read, export, or branch in the same PR unless compatibility requires keeping it. Whole-file deletions still require explicit instruction per rule 5 — propose the deletion in the PR body and leave the file until authorized. State in the PR what became obsolete.
20. **Judge complexity qualitatively, not numerically.** A simplification must remove decisions (dedupe checks, delete dead branches, table-drive repeated conditionals), not relocate them into one-use helpers to lower a metric. Tests follow the same bar: protect behavior, contracts, and regressions — not implementation details or coverage percentages.

# Intelligence Bar System

Natural-language AI command center embedded across admin + tech portals — one Express route (`server/routes/admin-intelligence-bar.js`), many contexts; tool modules in `server/services/intelligence-bar/{context}-tools.js` export `TOOLS` + `executeTool` (see rule 7). Three ambient rules:

1. **Write tools go through the UI-confirm trust boundary** (`write-gates.js` + its mirror contract test) — use the **`ib-write-tools` skill** for any tool that creates, updates, sends, or schedules.
2. **Every tool must pass the contract gate** (`npm run test:contracts` — schema, DB columns incl. raw SQL, execute smoke, response shape; runs in CI, warnings block). Write tools flag `sideEffects`, Claude-spawning tools flag `sonnetBacked`, UUID params declare `format: 'uuid'`.
3. **Tech portal is isolated** — `tech-tools` only, read-only, low max_tokens.

Everything else — architecture, the context→tools mapping, design decisions, the add-a-tool checklist — lives in the **`waves-ib` skill**: use it when adding or modifying any IB tool, context, or wrapper.

Email bounce rescue: `EMAIL_BOUNCE_TRANSCRIPT_RESCUE` (`off` disables the transcript-evidence rescue; default on, same convention as `EMAIL_BOUNCE_RECOVERY`), `RESCUE_SUGGESTION_EMAIL_TO` (ACT: suggestion recipient, default contact@).

Content publish gates: `GATE_COMPLIANCE` — the semantic compliance gate, an LLM second layer for `REENTRY_SAFETY_CLAIM` / `BANNED_TOPIC` catching the paraphrases regex cannot express. **Ships DARK: off unless set to exactly `true`.** It P0-blocks a publish, so calibrate before enabling — `node ops/agents/compliance-gate-eval.js --document --all` (live API keys required) reports recall/precision over the labelled corpus 23 Codex rounds produced. **`--document` is required for an activation decision**: without it the harness sends isolated sentences, which measures discrimination but not long-document recall or whether a banned topic reads as offered-by-Waves vs merely discussed — the context production always supplies. Treat the first clean run as provisional and hand-check a sample of both verdicts before flipping the flag. Once on, `GATE_COMPLIANCE=false` is the revoke. The regex layer in `content-guardrails.js` is unaffected either way and stays fail-closed. Also `MODEL_COMPLIANCE` (swaps the Anthropic leg only; OpenAI fallback stays) and `COMPLIANCE_TIMEOUT_MS` (default 60000, no retry — same ceiling as the fact-check gate).

LLM call ledger (agent control S2a): `GATE_LLM_CALL_LEDGER` — **ships DARK: off unless exactly `true`**, read at call time (unset = kill). On, every provider call through `server/services/llm/call.js` / `deep.js` and every Managed Agents session writes a `row_kind` `call` / `session` row to `llm_dispatch_log` (tokens incl. cache read/write + reasoning, latency, served model, lane / run correlation); `GATE_LLM_CALL_TRACES` (needs the ledger gate) keeps redacted prompt / response bodies in `llm_call_traces` for lanes whose runtime policy sets `trace: true`, pruned at 7 days. The chain rows and digest under `GATE_LLM_DISPATCH_METRICS` are unaffected either way. `GATE_AGENT_CONTROL_READ` (S2d, **dark**, read at call time) serves the Agents hub Control center reads — `/api/admin/agents/control/areas` + `/control/lanes` over the ledger (ET windows today/7d/30d, per-lane ok / fallback rate, p50/p95 latency, tokens, attention status) and flips `features.ledger` on the hub probe; off = both 404.

Zelle payment-notice reconciler: `GATE_ZELLE_NOTICE_RECONCILE` — **ships DARK: off in prod unless exactly `true`**, read at call time (unset = live kill). On, the Gmail sync settles an authenticated Capital One "sent you money with Zelle" notice against the ONE open self-pay invoice it matches (exact cents + payer name or memo invoice number) through `recordManualPayment` — receipt email + SMS included (owner ruling 2026-09-02) — and parks everything else on the Invoices page for one-click Apply / Ignore.

Affiliate links (blog monetization pilot): `GATE_AFFILIATE_LINKS` — strict opt-in; blog bodies reference owner-approved products by id through `<AffiliateLink product="…">`, resolved against the vendored `packages/affiliate-registry` (source of truth in the astro repo; `npm run sync:affiliate-registry`). Risk classes, page eligibility, disclosure, density, and refresh rules are in `content-guardrails.js`; autonomous supporting blogs need no per-post approval (the PR poller validates the current head against the live registry; other content lanes retain their existing approval contract); playbook in `docs/affiliate-links-pilot.md`.

Voice recovery evidence: `GATE_VOICE_RELAY_RECOVERY` — off unless exactly `true`, read at write time. Verified lead capture and re-service filing stamp their call metadata in the artifact transaction so a later session can distinguish a committed artifact from a failed write. Unset to disable.

Call transcription tunables: `OPENAI_TRANSCRIPTION_MODEL` / `OPENAI_TRANSCRIPTION_KEYWORDS` (CSV of literal keyword hints, gpt-transcribe family only), `CALL_PROC_MIN_AUDIO_BYTES_PER_SEC` (partial-download floor, default 3000), `CALL_PROC_EARLY_PROCESS_DELAY_MS` (early verified attempt, default 2 min).

Voice relay (Sandy) tuning: `VOICE_RELAY_PROFILE` — the id of a code-reviewed `RELAY_PROFILES` entry (`server/services/voice-agent/relay-profiles.js`, the only place `<ConversationRelay>` STT / turn-taking attributes are chosen); unset = the untuned relay, byte-identical TwiML; an unknown or sandbox-only id falls back to unset with one warning. `VOICE_RELAY_SANDBOX_NUMBER` — E.164 of the test number; enables `POST /api/webhooks/twilio/relay-sandbox`, the ONLY Sandy test path. **Enforced: a number `config/twilio-numbers.js` registers as a live line is refused** (403 on every call, one error log) — only an unregistered number or one parked under `unassigned` is eligible (the former GA# is still registered as Google Ads — Pest; park it first): every sandbox call gets a `call_log` row with `source='voice_relay_sandbox'` that the calls tab, unified inbox, and audits exclude, and a two-digit DTMF cell code inside the first 3 s selects a profile (`SANDBOX_CELLS`). `VOICE_RELAY_SANDBOX_ATTRS` — raw attribute JSON for sandbox cell `99` only. Per-call latency and version stamps land in `call_log.transcription_metadata.latency` / `.versions`. `GATE_VOICE_RELAY_INTERRUPT_CONTEXT` — **ships DARK: off unless set to `true`**, read at call time (a flip needs no redeploy): on, a barge-in rewrites the cut reply in the model's history to the played-text record (`… [interrupted]`) and prefixes the next caller message with what the caller heard, so Sandy resumes instead of repeating the unheard clause; off, a barge-in only aborts the generation and the model's messages are byte-identical to today. Transcript and stored record are unaffected either way. `GATE_VOICE_RELAY_RECOVERY` — **ships DARK: off unless set to `true`**, read at call time: on, a relay socket that fails mid-call is reconnected ONCE (`/relay-complete` re-renders the relay with a resumed greeting; the new socket takes the claim), every socket's turns land as a segment in `call_log.metadata.relay_segments` and the owning close composes the whole transcript, a second failure hands the caller to the office (transfer gate on, office open) or voicemail, and a second consecutive model / tool failure hands off instead of re-prompting; off, `/relay-complete` and the close-time writes are byte-identical to today. `GATE_VOICE_RELAY_TRANSFER` — **ships DARK: off unless exactly `true`**, read at call time: on, and only while the office is open at the session's first turn, Sandy gets `transfer_to_office` — the caller is handed to the existing staff simul-ring (press-1 screen, then a ≤20-word whisper read from the row) with a server-built packet on `call_log.metadata.relay_handoff` and `call_outcome='ai_transferred'`; after hours the tool is absent and she offers a callback through `capture_lead`. A packet write failure still transfers and rings the `sandy_transfer_no_context` bell. Off ⇒ no tool, prompt and `/relay-complete` byte-identical to today. Sandbox transfers hang up instead of ringing staff.
