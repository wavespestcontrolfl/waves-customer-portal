# Recovery attribution follow-up to PR #4437

Status: design proposal; implementation is separate from the safety change.

Persist the recovery result with the call processing result. Triage cards remain operator tasks; their status, timestamps, and payload edits must not establish a promotion cohort.

Define the recovery contract as the full set of prompts and models that can shape a recovery candidate on the current deployment, whichever path a given call takes: the primary transcription provider and model, the contact-pass transcription model and the `CONTACT_DICTATION_TRANSCRIPTION_PROMPT` version, the contact-decoder model and prompt version, and the recovery module's own prompt version and resolved model. The decoder consumes both the primary and the contact-pass transcripts (`contact-dictation.js` `buildDecoderPrompt`), so a change to either transcription contract changes the street alternatives even when the decoder and recovery pairs are unchanged. The contract epoch is one composite hash over all of these identities, computed from the configuration active when the processing generation is claimed.

Add a nullable JSONB field on call_log for the finalized recovery result. Every finalized row carries the contract epoch, the execution timestamp, and processing_generation, whether recovery was attempted or skipped; skipped rows are stamped with the same epoch so that no interval of the deployment is invisible to the cohort boundary. Attempted rows additionally carry the recovery method (autocomplete, dictation, phonetic), the individual identities of the contracts that produced candidates for that method, and the recovered/failed outcome. Capture every identity at execution, not when a later card is filed. Store only contract identity and outcome, without candidate streets or transcript text.

Clear or mark the result pending when claiming a new processing generation. Finalize it under the same processing_token guard as the routing result. Interrupted, unprocessed, legacy, or generation-mismatched rows are unattributable and excluded with explicit counts. A skipped result is current only when it belongs to the finalized processing generation; absence must never mean skipped. Preserve compatibility for older deployed workers: missing attribution cannot produce a positive readiness verdict.

The readiness command reads this field directly. Attempted rows qualify only when their contract epoch equals the current epoch, which means every prompt and model in the contract, not the recovery pair alone. A recovered result reconstructs an accepting address verdict only for that same finalized processing result. A failed result keeps its failure verdict. Triage card creation, resolution, reopening, and timestamp changes have no effect on the cohort.

Contract identity alone cannot separate rollback epochs: after an A → B → A prompt or model rollback, every pre-B A result matches the restored contract again, and processing_generation only orders passes within one call. The readiness command therefore bounds the cohort the way `scripts/v2-promotion-readiness.js` already does for extraction models: the cohort is the contiguous run of finalized rows, attempted or skipped, after the newest row whose epoch differs from the current epoch, ordered by execution timestamp. Because skipped rows carry the epoch, a B interval in which no call attempted recovery still produces the boundary, and pre-B successes are excluded. `--since <ISO date>` is the operator override, and the deployment activation timestamp of the current contract, when recorded, is the default cutoff in preference to the derived boundary. When neither exists and a flip inside the current contract set cannot be ruled out, the command fails closed and prints the same warning instead of returning a verdict, so a freshly restored contract must produce post-rollback evidence before it can pass.

Restore the readiness command only after database tests prove: success → failure → success; failed → skipped → failed; prompt changes; model changes and rollbacks, including A → B → A with pre-B samples excluded from the cohort, and the same sequence where every B-interval row is a skipped recovery; a primary transcription or contact-pass transcription prompt change that leaves the decoder and recovery pairs unchanged; a contact-decoder prompt or model change that leaves the recovery pair unchanged; stale worker after claim loss; crashes between extraction, recovery, routing, and finalization; historical rows without attribution; and operator mutations of all related cards.

The original experimental implementation is retained in commit 6016932fc on PR #4437 for investigation. It is reference material, not the implementation proposed here.
