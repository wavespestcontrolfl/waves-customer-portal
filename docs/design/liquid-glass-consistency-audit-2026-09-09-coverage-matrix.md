# Liquid Glass consistency audit — route/state coverage matrix (2026-09-09)

Generated by `scripts/qa/glass-audit/matrix.cjs` from the capture summaries under `.tmp/glass-audit/`. Companion to `liquid-glass-consistency-audit-2026-09-09.md`.

**Environment actually tested.** Headless Google Chrome (installed stable build, driven by Playwright 1.59 via `scripts/qa/browser.js launchBrowser`) on macOS for every scenario; WebKit (Playwright build 2272, headless) for the `webkit390` pass on eleven representative scenarios at 390px. Viewports: 390×844 and 1440×1000 for every scenario; 320/375/430/768/1024 for scenarios flagged `extraWidths`; 640 for emails. Device pixel ratio 1, `America/New_York`, service workers blocked, every external origin blocked, every `/api/*` call answered by a synthetic fixture. **No real iPhone, iOS Safari, installed PWA, notch/safe-area, or physical touch was tested.** Reduced motion was emulated (`prefers-reduced-motion: reduce`); forced colours (`forced-colors: active`) are emulated as registered states on two scenarios; `prefers-reduced-transparency` and a no-`backdrop-filter` engine could not be emulated.

**Status vocabulary.** `inspected` = the latest capture (runs in generation order) of every declared state at that width succeeded with metrics in every engine that captured it; an earlier success never masks a later failed re-run, and a Chromium re-run never supersedes a WebKit capture (a failed latest WebKit capture shows as `partial (…; latest webkit capture failed)`). `partial` = the latest capture of some states failed. `NOT VERIFIED` = no capture at that width. `BLOCKED` = the latest capture of every state at that width failed. A scenario absent from this table was not rendered.

**Surface families.** `portal-app` = the authenticated customer PWA (`PortalPage`, preview harness `preview-portal.html`, no `WavesShell`); `estimate`, `document-report`, `document-billing`, `document-outline`, `document-newsletter`, `document-diagnostic` = token documents under `WavesShell`; `flow` = appointment / track / secure / reschedule / re-service / prep / rate; `booking` = `/book`; `auth` = login and the app-level auth screens; `card` = digital business card; `error-states` = the 404 / load-error card on six families; `email` and `newsletter-landing` = server-rendered HTML; `theme-scope` = admin and tech probes (not glass surfaces; captured to prove scoping); `showcase` = the dev-only tokens page. Preview-harness scenarios (`10-previews.cjs`) render the real page component without `WavesShell`; the `spa-*` scenarios (`70-spa-parity.cjs`) render the same fixtures through the real `App.jsx` route so shell chrome is proven there.
