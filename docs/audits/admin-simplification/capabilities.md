# Capability and disposition map

This is the pre-change capability inventory and proposed ownership. Implementation status is separate from the target. **A** = authenticated `admin`; **S** = authenticated `admin` or `technician`, with per-action guards still applied. There is no independent office role in the current authentication contract. “S shell” does not grant the union of every child/API permission. Source paths below are relative to the repository; exact symbols, lines, subordinate components and direct request methods are indexed in [module-index.csv](module-index.csv). API prefixes have `/api` prepended in production.

## Shared side effects and consumer boundaries

Source reachability is broader than React imports. `server/index.js` mounts routes explicitly; `server/services/scheduler.js` and feature-specific jobs run independently of the sidebar. Notification templates are consumed by messaging, invoice/receipt, scheduling and report paths. Newsletter Events have ingestion/merge/planning consumers. Agent task/draft producers persist state before any UI opens. The Intelligence Bar executes through the existing authorization contract, write-gates/pending-actions, thread store and tool registry. Stripe events use the sole raw-body/idempotent webhook; customer token routes remain permanent or one-shot according to their documented contracts.

Opening a page is not universally read-only: SMS/email detail can mark read, template preview and AI scan can invoke providers, OAuth/navigation can initiate connection work, dispatch/estimate panels have write controls and telemetry beacons POST. Browser fixtures therefore intercept **all** API requests, forbid unexpected mutations, block external origins and service workers, and do not boot the backend or jobs. Saved state, DB-held links, integrations and seasonal usage remain unavailable evidence, not permission to delete.
